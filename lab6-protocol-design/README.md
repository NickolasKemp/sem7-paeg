# Лабораторна робота №6 (ПАЕГ) — проєктування протоколу Е-голосування

Власний протокол Е-голосування: **БР** (сліпий ЕЦП мандатів, ключ на кожну дільницю), **4 ДВК** у двох гілках
(ДВК-1.d, ДВК-2.d для дільниць d = 1, 2), **2 СВК** (по одній на гілку), **ЦВК** (ключ шифрування, об'єднання
частин, розшифрування, підрахунок) і публічний аудит. Бюлетень ділиться в групі Z*ₙ: m₁ випадкове,
m₂ = m · m₁⁻¹ mod n; частини шифруються RSA ключем ЦВК і об'єднуються гомоморфно C₁ · C₂ mod n.
Уся арифметика RSA, хеш квадратичної згортки і сліпий підпис написані вручну (перенесено з ЛР1, ЛР2, ЛР4).

## Запуск

```bash
npm start        # демонстрація: штатне голосування, негативні сценарії, атаки організаторів, таємниця голосу
npm test         # 17 модульних тестів (node:test)
npm run typecheck
```

Перегенерація матеріалів звіту:

```bash
npm run shots    # скріншоти виконання і схема протоколу → assets/*.png
npm run report   # звіт → report/Звіт_ЛР6_ПАЕГ_Туболев.docx і .pdf
```

Потрібен Node.js ≥ 22.6 (TypeScript виконується напряму, без збірки).

## Структура

| Файл | Призначення |
| --- | --- |
| `src/bigint-math.ts`, `src/rsa.ts` | арифметика, RSA, `multiplyCiphers`, хеш, ЕЦП |
| `src/blind-signature.ts` | `H' = H·rᵉ`, `S' = (H')ᵈ`, `S = S'·r⁻¹` |
| `src/types.ts` | мандат, частина бюлетеня, пакет, результати, причини відмов |
| `src/message.ts` | серіалізація, підписані повідомлення, `validatePart` — спільні перевірки ДВК/СВК/ЦВК |
| `src/voter.ts` | виборець: мандат, сліпа реєстрація, `splitBallot`, перевірки публікацій |
| `src/bureau.ts` | БР: реєстр громадян, перевірки, сліпий ЕЦП, списки зареєстрованих |
| `src/lower-commission.ts` | ДВК: прийом частини, одноразовість, підписана публікація |
| `src/middle-commission.ts` | СВК: пакети ДВК, повторні перевірки, дублікати, скарги |
| `src/central-commission.ts` | ЦВК: кандидати, перевірка пакетів, об'єднання → розшифрування, підрахунок |
| `src/audit.ts` | публічний аудит лише за опублікованими даними |
| `src/attacks.ts` | нечесні БР, ДВК, СВК; перебір значень частини |
| `src/main.ts` | сценарій демонстрації |
| `tools/scheme.html` | структурно-функціональна схема (SVG → `assets/00-scheme.png`) |

Дані кожного учасника — приватні поля (`#…`); модулі не мають посилань один на одного й отримують лише відкриті
ключі та повідомлення. Пакети між комісіями підписані ЕЦП відправника.

## Сценарії

Штатні: 8 виборців на 2 дільницях, 3 кандидати; виборці і аудит підтверджують результат.

Негативні: `NOT_IN_ROLL`, `IDENTITY_MISMATCH`, `NO_VOTING_RIGHT`, `WRONG_DISTRICT`, `ALREADY_REGISTERED` у БР;
`NOT_ELIGIBLE`, `BAD_SIGNATURE`, `WRONG_COMMISSION`, `ALREADY_VOTED` у ДВК.

Атаки: «мертві душі» від БР (виявляється лише при перевищенні кількості зареєстрованих), вкидання, підміна і
втрата частин у ДВК (СВК відкидає, скарга виборця відновлює), підміна в СВК, нечесна ЦВК (аудит `mᵉ mod n = C₁·C₂`),
перебір частини і змова БР + ЦВК (зв'язок «особа — голос» не встановлюється).
