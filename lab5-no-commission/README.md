# Лабораторна робота №5 (ПАЕГ) — протокол Е-голосування без виборчої комісії

Програмна реалізація протоколу з перемішуванням бюлетенів: **2 кандидати, 5 виборців** (A, B, C, D, E),
жодної комісії чи іншої довіреної сторони. Кожен виборець генерує власну пару ключів RSA, шифрує бюлетень
двома раундами посимвольного багатошарового RSA (E → D → C → B → A) з власним RP перед своїм шаром, а потім
усі по черзі (A → B → C → D → E, два раунди) знімають свої шари, перевіряють ЕЦП попереднього учасника,
кількість бюлетенів і власний RP, перемішують і підписують набір. Уся арифметика RSA, хеш квадратичної
згортки та ЕЦП написані вручну, без криптобібліотек.

## Запуск

```bash
npm start        # демонстрація: протокол, негативні сценарії, аналіз властивостей і складності
npm test         # 17 модульних тестів (node:test)
npm run typecheck
npm run shots    # скріншоти виконання → assets/*.png
npm run report   # звіт → report/Звіт_ЛР5_ПАЕГ_Туболев_Шамков.docx і .pdf
```

Потрібен Node.js ≥ 22.6 (TypeScript виконується напряму, без збірки).

## Рішення, що відходять від методички

- Символ — 16-бітна кодова одиниця рядка, модуль RSA — 32 біти: шифротекст символу займає два символи,
  тож кожен шар подвоює довжину.
- Символи в межах шару зчеплено: `cᵢ = ((mᵢ + cᵢ₊₁) mod n)^e mod n`. Без цього
  `RSA(X || RP) = RSA(X) || RSA(RP)`, RP нічого не приховує, і голос впізнається за відкритими ключами.
- EVP доповнюється пробілами до спільної довжини, щоб довжина шифротексту не видавала вибір.

## Сценарії

Позитивний: 10 етапів розшифрування, підсумок 3 : 2, однаковий підрахунок у всіх п’яти учасників.

Негативні: зайвий бюлетень (`COUNT_MISMATCH` у A), видалений бюлетень із чесним підписом (`COUNT_MISMATCH` у D),
зміна набору в каналі та підпис чужим ключем (`BAD_SIGNATURE`), сфабрикований бюлетень (`RP_NOT_FOUND`, перший раунд),
підробка з чужим RP (`RP_NOT_FOUND`, другий раунд), копія чужого бюлетеня (`RP_DUPLICATE`), відмова учасника
(`NOT_RECEIVED`), хибний оголошений підсумок (`TALLY_MISMATCH`).

Аналіз: довжина бюлетеня видає позицію власника; D після свого кроку в другому раунді розпізнає голоси A–D і
дізнається вибір E; обсяг даних росте як 4^N.
