1. Тема, мета та завдання роботи

Тема: протокол Е-голосування без виборчої комісії.

Мета роботи: програмно реалізувати протокол електронного голосування без виборчої комісії для двох кандидатів і п’яти виборців, у якому всі операції — багатошарове шифрування бюлетенів, їх передачу, розшифрування, перемішування та підрахунок — виконують самі виборці; дослідити, як випадкові рядки RP, контроль кількості бюлетенів і ЕЦП наборів дозволяють учасникам виявляти втручання, а також з’ясувати обмеження протоколу.

Завдання роботи:

  • сформувати спільний впорядкований список виборців і кандидатів та визначити послідовність виконання протоколу;
  • реалізувати самостійну генерацію кожним виборцем пари ключів RSA та обмін відкритими ключами між усіма учасниками;
  • реалізувати формування виборцем власного електронного бюлетеня і посимвольне багатошарове RSA-шифрування, за якого результат попереднього шару є вхідними даними наступного;
  • виконати два раунди шифрування відкритими ключами всіх виборців у порядку E → D → C → B → A з генерацією, додаванням і збереженням власних RP перед власним шаром у кожному раунді;
  • передати всі повністю зашифровані бюлетені першому виборцю та перевіряти кількість бюлетенів перед початком і на кожному наступному етапі;
  • виконати два раунди розшифрування A → B → C → D → E: зняття власного шару з усіх бюлетенів, перевірку і видалення власного RP (у першому раунді — доданого в другому раунді шифрування, у другому — доданого в першому), випадкове перемішування, ЕЦП набору перед передачею та перевірку ЕЦП попереднього учасника;
  • отримати початкові відкриті бюлетені, опублікувати остаточний набір, підрахувати голоси та виконати незалежний повторний підрахунок кожним учасником;
  • перевірити негативні сценарії: зміну кількості бюлетенів (додавання та видалення), неправильний ЕЦП набору, відсутній або неправильний RP, а також однаковість результату підрахунку в усіх учасників.

2. Короткий опис програмної реалізації

Протокол реалізовано мовою TypeScript і виконується середовищем Node.js без етапу збірки. Криптографічні бібліотеки не використовувалися: модульна арифметика, генерація простих чисел, розширений алгоритм Евкліда, RSA, хеш квадратичної згортки та ЕЦП написані вручну (модуль арифметики перенесено з попередніх лабораторних робіт). Єдиний тип учасника — виборець: окремої комісії чи іншої довіреної сторони в коді немає. Модуль election.ts лише передає дані від одного виборця до наступного в порядку спільного списку, а всі перевірки виконує сам виборець над власною копією списку і власними ключами. Для моделювання атак передача набору проходить через функцію втручання, яка може змінити, переписати або не доставити набір.

2.1. Спільний список виборців і обмін відкритими ключами

Учасники домовляються про впорядкований список A, B, C, D, E (порядок реєстрації), який водночас задає послідовність виконання протоколу: шифрування в кожному раунді йде від кінця списку до початку, розшифрування — від початку до кінця, результат публікує останній виборець. Кожен виборець самостійно генерує пару ключів RSA (p і q — 16-бітні прості, n = p · q — 32 біти, e = 65537, d = e⁻¹ mod φ(n) розширеним алгоритмом Евкліда) і оголошує відкритий ключ. З оголошень кожен складає власну копію списку і перевіряє, що в ній є він сам зі своїм ключем; однаковість усіх копій підтверджується однаковим відбитком SHA-256.

/**
 * Крок 1: учасники домовляються про впорядкований список (порядок реєстрації),
 * кожен генерує ключі й оголошує відкритий ключ, кожен складає власну копію списку.
 */
export function registerVoters(names: readonly string[]): Voter[] {
  const voters = names.map((name) => new Voter(name));
  const announcements = voters.map(({ name, publicKey }) => ({ name, publicKey }));
  for (const voter of voters) voter.acceptRoster(announcements.map((entry) => ({ ...entry })));
  return voters;
}

/** Крок 1: виборець зберігає власну копію спільного списку з відкритими ключами. */
acceptRoster(roster: Roster): void {
  const own = roster.find((entry) => entry.name === this.name);
  if (own?.publicKey.n !== this.publicKey.n || own.publicKey.e !== this.publicKey.e) {
    throw new Error(`${this.name}: у списку немає мене з моїм відкритим ключем`);
  }
  this.#roster = [...roster];
}

2.2. Посимвольне багатошарове RSA-шифрування

Символом вважається одна кодова одиниця рядка (UTF-16, значення 0…65535), тому кожен символ шифрується окремо як число, менше за модуль n. Шифротекст символу — 32-бітне число, яке записується двома символами, отже результат шару знову є рядком і може бути вхідними даними наступного шару, а кожен шар подвоює довжину.

Якщо шифрувати символи незалежно (cᵢ = mᵢ^e mod n), шифрування стає простою заміною символів, і RSA(X || RP) = RSA(X) || RSA(RP): дописаний у кінець RP не впливає на шифротекст бюлетеня. Тоді будь-хто, знаючи відкриті ключі зі спільного списку, міг би зашифрувати ім’я кожного кандидата і впізнати голос кожного виборця за початком шифротексту. Тому в межах шару символи зчеплено у зворотному напрямку: cᵢ = ((mᵢ + cᵢ₊₁) mod n)^e mod n, де за останнім символом стоїть c = 0. Кожен символ, як і раніше, шифрується окремою операцією RSA, але залежить від шифротексту символу праворуч, тож RP, дописаний у кінець, змінює весь шар. Розшифрування: mᵢ = (cᵢ^d − cᵢ₊₁) mod n; якщо значення виходить за модуль або алфавіт, шар вважається зашифрованим не цим ключем.

/**
 * Один шар посимвольного RSA зі зворотним зчепленням символів:
 * cᵢ = ((mᵢ + cᵢ₊₁) mod n)^e mod n, де за останнім символом стоїть c = 0.
 * Кожен символ шифрується окремо, але залежить від усіх символів праворуч,
 * тому дописаний у кінець RP змінює весь шифротекст шару.
 */
export function encryptLayer(text: string, key: PublicKey): string {
  const values = new Array<bigint>(text.length);
  let next = 0n;
  for (let index = text.length - 1; index >= 0; index -= 1) {
    next = modPow((BigInt(text.charCodeAt(index)) + next) % key.n, key.e, key.n);
    values[index] = next;
  }
  return values.map(packValue).join("");
}

/**
 * Зняття шару закритим ключем: mᵢ = (cᵢ^d − cᵢ₊₁) mod n.
 * Повертає undefined, якщо шар зашифровано не цим ключем
 * (непарна довжина, значення поза модулем або символ поза алфавітом).
 */
export function decryptLayer(cipher: string, key: PrivateKey): string | undefined {
  if (cipher.length % 2 !== 0) return undefined;
  const values = unpackValues(cipher);

  let text = "";
  for (let index = 0; index < values.length; index += 1) {
    const value = values[index]!;
    if (value >= key.n) return undefined;
    const next = values[index + 1] ?? 0n;
    const symbol = (modPow(value, key.d, key.n) - next % key.n + key.n) % key.n;
    if (symbol >= SYMBOL_COUNT) return undefined;
    text += String.fromCharCode(Number(symbol));
  }
  return text;
}

2.3. Бюлетень і два раунди шифрування з RP

Електронний бюлетень EVP — ім’я обраного кандидата, доповнене пробілами до спільної довжини, щоб довжина шифротексту не видавала вибір. Один раунд шифрування накладає шари відкритими ключами всіх виборців у порядку E → D → C → B → A; перед власним шаром виборець дописує новий RP (4 символи, 64 біти з криптографічно стійкого генератора) і зберігає його. Другий раунд повторює те саме над шифротекстом першого раунду з новим RP. Для виборця C це дає C₁ = RSA_A(RSA_B(RSA_C(RSA_D(RSA_E(EVP)) || RP¹_C))) і C₂ = RSA_A(RSA_B(RSA_C(RSA_D(RSA_E(C₁)) || RP²_C))), як у методичних вказівках.

/**
 * Електронний бюлетень (EVP) — ім'я кандидата, доповнене пробілами до спільної довжини:
 * інакше довжина шифротексту видавала б вибір.
 */
export function formBallot(candidate: Candidate, candidates: readonly Candidate[]): string {
  const width = Math.max(...candidates.map(({ name }) => name.length));
  return candidate.name.padEnd(width, " ");
}

/**
 * Один раунд багатошарового шифрування: шари накладаються у порядку, зворотному
 * до порядку розшифрування (для A, B, C, D, E — це E → D → C → B → A),
 * результат кожного шару є вхідними даними наступного. Перед шаром учасника,
 * для якого задано RP, цей RP дописується в кінець поточного повідомлення.
 */
export function wrapLayers(
  message: string,
  chain: Roster,
  rpFor: (entry: RosterEntry) => string | undefined = () => undefined,
  onLayer?: (trace: LayerTrace) => void,
): string {
  let current = message;
  for (const entry of [...chain].reverse()) {
    const rp = rpFor(entry);
    if (rp !== undefined) current += rp;
    current = encryptLayer(current, entry.publicKey);
    onLayer?.({ layer: entry.name, rpAdded: rp !== undefined, length: current.length });
  }
  return current;
}

/** Крок 2: ROUNDS раундів багатошарового шифрування; перед власним шаром — новий RP. */
castBallot(evp: string, onLayer?: (trace: LayerTrace & { readonly round: number }) => void): string {
  let message = evp;
  for (let round = 0; round < ROUNDS; round += 1) {
    const rp = randomRp();
    this.#rp[round] = rp;
    const ownLayer = (entry: RosterEntry) => (entry.name === this.name ? rp : undefined);
    message = wrapLayers(message, this.#roster, ownLayer, (trace) => onLayer?.({ ...trace, round }));
  }
  return message;
}

/** RP, який виборець шукає в раунді розшифрування: раунди знімаються у зворотному порядку. */
rpFor(decryptionRound: number): string {
  const rp = this.#rp[ROUNDS - 1 - decryptionRound];
  if (rp === undefined) throw new Error(`${this.name}: бюлетень ще не зашифровано`);
  return rp;
}

2.4. Етап розшифрування одного виборця

Отримавши набір, виборець спершу визначає за своєю копією списку, від кого він має надійти: від попереднього учасника, для першого виборця в другому раунді — від останнього, а на самому початку — від усіх виборців (зібраний набір). Далі перевіряються відправник, ЕЦП набору відкритим ключем відправника і кількість бюлетенів. Після цього виборець знімає свій шар з усіх бюлетенів, шукає бюлетень, що закінчується його RP (у першому раунді розшифрування — RP², у другому — RP¹), видаляє RP, перемішує набір алгоритмом Фішера — Єйтса з криптографічно стійким генератором і підписує його. Відсутність власного RP та його наявність у кількох бюлетенях обробляються як різні порушення.

/** Від кого виборець очікує набір: попередній у списку, а для першого — останній з попереднього раунду. */
expectedSender(decryptionRound: number): RosterEntry | undefined {
  const position = this.#roster.findIndex((entry) => entry.name === this.name);
  if (position > 0) return this.#roster[position - 1];
  if (decryptionRound > 0) return this.#roster.at(-1);
  return undefined;
}

/**
 * Кроки 3–4: перевірка відправника та його ЕЦП, кількості бюлетенів, зняття власного шару
 * з усіх бюлетенів, пошук і видалення власного RP, перемішування і підпис набору.
 */
processSet(incoming: IncomingSet, decryptionRound: number): StepResult {
  const expected = this.expectedSender(decryptionRound);
  if (expected === undefined) {
    if (incoming.kind !== "collected") return reject("UNEXPECTED_SENDER", `очікувалися бюлетені від усіх виборців, а надійшов набір від ${incoming.from}`);
  } else {
    if (incoming.kind !== "signed" || incoming.from !== expected.name) {
      return reject("UNEXPECTED_SENDER", `очікувався набір від ${expected.name}`);
    }
    const signatureValid = verify(serializeSet(incoming.from, incoming.ballots), incoming.signature, expected.publicKey);
    if (!signatureValid) return reject("BAD_SIGNATURE", `ЕЦП набору не відповідає відкритому ключу ${expected.name}`);
  }

  const expectedCount = this.#roster.length;
  if (incoming.ballots.length !== expectedCount) {
    return reject("COUNT_MISMATCH", `отримано бюлетенів: ${incoming.ballots.length}, учасників: ${expectedCount}`);
  }

  const decrypted: string[] = [];
  for (const ballot of incoming.ballots) {
    const opened = decryptLayer(ballot, this.keys.privateKey);
    if (opened === undefined) return reject("BAD_CIPHERTEXT");
    decrypted.push(opened);
  }

  const rp = this.rpFor(decryptionRound);
  const own = decrypted.filter((ballot) => ballot.endsWith(rp));
  if (own.length === 0) return reject("RP_NOT_FOUND", `власний RP з раунду шифрування ${ROUNDS - decryptionRound} відсутній`);
  if (own.length > 1) return reject("RP_DUPLICATE", `власний RP знайдено у ${own.length} бюлетенях — хтось скопіював бюлетень`);

  const stripped = decrypted.map((ballot) => (ballot.endsWith(rp) ? ballot.slice(0, -rp.length) : ballot));
  return { ok: true, output: this.signSet(shuffle(stripped)), verifiedSender: expected?.name, rp };
}

signSet(ballots: readonly string[]): SignedSet {
  return { kind: "signed", from: this.name, ballots, signature: sign(serializeSet(this.name, ballots), this.keys.privateKey) };
}
Лістинг 5 — Перевірки, зняття шару, пошук RP, перемішування і ЕЦП (src/voter.ts)

Підписується канонічний текст набору: ім’я відправника і всі бюлетені, кожен з префіксом довжини, бо шифротекст може містити будь-які символи. ЕЦП обчислюється як H^d mod n, де H — хеш квадратичної згортки Hᵢ = (Hᵢ₋₁ + Mᵢ)² mod n, а перевіряється порівнянням H з ЕЦП^e mod n.

/**
 * Канонічний текст набору — саме він хешується і підписується.
 * Шифротекст може містити будь-які символи, тому кожен бюлетень записано з довжиною.
 */
export function serializeSet(from: string, ballots: readonly string[]): string {
  return `${from}|${ballots.map((ballot) => `${ballot.length}:${ballot}`).join("")}`;
}

/** Формування ЕЦП закритим ключем: ЕЦП = H^d mod n. */
export function sign(message: string, key: PrivateKey): bigint {
  return modPow(hashMessage(message, key.n), key.d, key.n);
}

/** Перевірка ЕЦП: порівнюємо H і H_c = ЕЦП^e mod n. */
export function verify(message: string, signature: bigint, key: PublicKey): boolean {
  return hashMessage(message, key.n) === modPow(signature, key.e, key.n);
}

2.5. Передача наборів між виборцями

Функція mix передає зібраний набір першому виборцю і далі веде його по колу: у кожному з двох раундів розшифрування етап виконують усі виборці в порядку списку, після E набір повертається до A. Якщо будь-який виборець відхиляє набір або набір не надійшов, протокол зупиняється з зазначенням, хто і на якому етапі виявив порушення. Остаточний набір, підписаний останнім виборцем, містить відкриті бюлетені.

/** Кроки 3–4: ROUNDS раундів розшифрування, у кожному — усі виборці в порядку списку. */
export function mix(
  voters: readonly Voter[],
  ballots: readonly string[],
  options: { readonly tamper?: Tamper; readonly onStep?: (step: StepRecord) => void } = {},
): MixOutcome {
  const deliver = (hop: Hop, set: IncomingSet) => (options.tamper ? options.tamper(hop, set) : set);
  const first = voters[0];
  if (first === undefined) throw new Error("Немає учасників");

  const steps: StepRecord[] = [];
  let incoming = deliver({ kind: "collect", to: first.name }, { kind: "collected", ballots });
  let final: SignedSet | undefined;

  for (let round = 0; round < ROUNDS; round += 1) {
    for (const [index, voter] of voters.entries()) {
      if (incoming === undefined) {
        const failure = { reason: "NOT_RECEIVED", detail: "попередній учасник не передав набір — протокол зупинено" } as const;
        return { status: "aborted", steps, voter: voter.name, round, failure };
      }

      const result = voter.processSet(incoming, round);
      if (!result.ok) {
        return { status: "aborted", steps, voter: voter.name, round, failure: { reason: result.reason, detail: result.detail } };
      }

      const step = { round, voter: voter.name, received: incoming.ballots.length, verifiedSender: result.verifiedSender, output: result.output };
      steps.push(step);
      options.onStep?.(step);

      const next = voters[index + 1] ?? (round + 1 < ROUNDS ? first : undefined);
      if (next === undefined) {
        final = result.output;
        break;
      }
      incoming = deliver({ kind: "pass", round, from: voter.name, to: next.name }, result.output);
    }
  }

  if (final === undefined) throw new Error("Протокол завершився без остаточного набору");
  return { status: "completed", steps, final };
}

2.6. Публікація і незалежний підрахунок

Виборець E публікує остаточний набір зі своїм ЕЦП і оголошує підрахунок. Кожен учасник перевіряє, що набір опублікував саме останній виборець, ЕЦП, кількість бюлетенів, самостійно рахує голоси і порівнює свій результат з оголошеним. Бюлетень, що не збігається з жодним EVP, рахується недійсним.

/** Крок 5: перевірка опублікованого набору і самостійний повторний підрахунок голосів. */
verifyPublication(publication: Publication, candidates: readonly Candidate[]): VerificationResult {
  const publisher = this.#roster.at(-1);
  const { set } = publication;
  if (publisher === undefined || set.from !== publisher.name) {
    return reject("UNEXPECTED_SENDER", `результати має публікувати ${publisher?.name}`);
  }
  if (!verify(serializeSet(set.from, set.ballots), set.signature, publisher.publicKey)) {
    return reject("BAD_SIGNATURE", `ЕЦП опублікованого набору не відповідає ключу ${publisher.name}`);
  }
  if (set.ballots.length !== this.#roster.length) {
    return reject("COUNT_MISMATCH", `опубліковано бюлетенів: ${set.ballots.length}, учасників: ${this.#roster.length}`);
  }

  const tally = countVotes(set.ballots, candidates);
  if (!sameTally(tally, publication.announced)) return reject("TALLY_MISMATCH");
  return { ok: true, tally };
}

/** Підрахунок, який кожен учасник виконує самостійно над опублікованими бюлетенями. */
export function countVotes(ballots: readonly string[], candidates: readonly Candidate[]): Tally {
  const votes = new Map(candidates.map(({ id }) => [id, 0]));
  let invalid = 0;
  for (const evp of ballots) {
    const candidate = readBallot(evp, candidates);
    if (candidate === undefined) {
      invalid += 1;
      continue;
    }
    votes.set(candidate.id, (votes.get(candidate.id) ?? 0) + 1);
  }
  return { votes, invalid };
}

5. Висновок

У ході виконання лабораторної роботи програмно реалізовано всі кроки протоколу електронного голосування без виборчої комісії для двох кандидатів і п’яти виборців: формування спільного списку і обмін відкритими ключами, посимвольне багатошарове RSA-шифрування бюлетенів у двох раундах з власними RP, збір бюлетенів першим виборцем, два раунди розшифрування з перевіркою кількості, ЕЦП попереднього учасника і власного RP, перемішування після кожного етапу, публікацію результату і незалежний підрахунок кожним учасником.

Експериментально підтверджено, що контроль кількості виявляє додавання і видалення бюлетенів, ЕЦП наборів — зміну набору під час передачі та підробку відправника, а RP — заміну чи копіювання бюлетеня навіть тоді, коли кількість і підписи правильні. Хибний оголошений підсумок виявляє кожен учасник, бо всі отримують однаковий набір і рахують самостійно.

Водночас протокол має суттєві обмеження. Кожен шар подвоює довжину бюлетеня, тому обсяг даних росте як 4^N і вже для 10 виборців недосяжний. Відмова одного учасника зупиняє голосування. Довжина шифротексту видає позицію власника, а детермінованість RSA після видалення RP дозволяє останнім у черзі розпізнавати голоси попередніх: D дізнається вибір E. Підміну бюлетеня виборця, чий етап уже минув у поточному раунді, перевірка RP не виявляє — її виявив би лише власник у наступному раунді або порівняння з власним проміжним шифротекстом.

Відхилення від методичних вказівок і лекції: у межах шару символи шифруються зі зчепленням, бо без нього RP нічого не приховує; символ — 16-бітна кодова одиниця, модуль RSA — 32 біти, тому шифротекст символу займає два символи; EVP доповнюється до однакової довжини. Реалізовано варіант протоколу з методичних вказівок: у лекції RP додається до бюлетеня всередині (Vᵢ, R1ᵢ) і в кожному шарі другого етапу, а ЕЦП ставиться лише на другому етапі. Додатково змодельовано копіювання бюлетеня, відмову учасника, хибний підсумок і аналіз витоку інформації.

6. Відповіді на контрольні запитання

1. Опишіть послідовність роботи протоколу електронного голосування без виборчої комісії.

Учасники формують спільний впорядкований список виборців і кандидатів, кожен генерує пару ключів RSA і передає відкритий ключ іншим. Кожен виборець формує бюлетень і виконує два раунди шифрування відкритими ключами всіх виборців у порядку E → D → C → B → A, дописуючи перед власним шаром новий RP у кожному раунді та зберігаючи його. Усі бюлетені надсилаються виборцю A, який перевіряє їх кількість. У першому раунді розшифрування виборці A → B → C → D → E по черзі перевіряють ЕЦП попереднього учасника і кількість, знімають свій шар з усіх бюлетенів, знаходять і видаляють свій RP другого раунду, перемішують, підписують набір і передають далі. E передає набір A, і другий раунд повторює ці дії з RP першого раунду. Після кроку E отримано відкриті бюлетені; E публікує їх і підраховує голоси, а кожен учасник перевіряє набір і повторює підрахунок.

2. Для чого у протоколі використовується багатошарове шифрування бюлетенів та чому всі виборці повинні мати відкриті ключі інших учасників?

Багатошарове шифрування замінює довірену комісію: бюлетень відкривається лише тоді, коли свій шар знімуть усі виборці, тож жоден учасник і жодна їх неповна група не можуть прочитати чи підмінити бюлетень на початку протоколу. Кожен шар знімає свій власник, який водночас перевіряє набір і перемішує його, тому контроль розподілено між усіма. Відкриті ключі всіх учасників потрібні, бо кожен виборець сам накладає на свій бюлетень шари всіх інших, а також перевіряє ЕЦП попереднього учасника; однаковий у всіх список ключів гарантує, що ніхто не підставить фальшивий ключ.

3. Яку роль виконують випадкові рядки RP та чому для двох раундів шифрування використовуються різні RP?

RP — особиста мітка виборця всередині власного шару: знявши свій шар, виборець знаходить RP і переконується, що його бюлетень присутній у наборі й не замінений; відсутність RP або його наявність у кількох бюлетенях означає підміну чи копіювання. Крім того, RP робить шифротексти однакових бюлетенів різними (у нашій реалізації — завдяки зчепленню символів). Різні RP потрібні, бо кожен раунд розшифрування перевіряє свою мітку: перший — RP² (бюлетень не втрачено до початку розшифрування), другий — RP¹ (бюлетень не підмінено під час першого раунду). Незалежні RP роблять ці перевірки незалежними: якщо виборцю доведеться розкрити RP, щоб довести порушення, або RP одного раунду стане відомим іншим чином, мітку другого раунду це не знецінить; крім того, однаковий RP у двох шарах пов’язував би шифротексти раундів між собою.

4. Для чого після кожного етапу розшифрування виконується випадкове перемішування бюлетенів?

Перемішування руйнує зв’язок між позицією бюлетеня і його власником: бюлетені надходять до A у порядку відправників, і без перемішування після зняття всіх шарів кожен бачив би, чий голос на якій позиції. Оскільки перемішує кожен виборець, для зв’язування бюлетеня з власником довелося б об’єднати знання всіх учасників. Як показав аналіз, у посимвольній реалізації довжина шифротексту видає позицію власника, доки його RP не видалено, тому перемішування дієве лише разом з однаковою довжиною бюлетенів на кожному етапі.

5. Для чого під час передачі набору бюлетенів між виборцями використовується ЕЦП та перевіряється кількість бюлетенів?

ЕЦП набору засвідчує, що набір надіслав саме попередній учасник і що його не змінено під час передачі; у разі виявлення порушення підписи дозволяють простежити ланцюжок і встановити, хто передав некоректний набір. Перевірка кількості виявляє додавання чи видалення бюлетенів, яке ЕЦП не виявляє, якщо порушник — сам відправник: у демонстрації C видалив бюлетень і чесно підписав набір, і лише D за кількістю зупинив протокол.

6. Чому протокол потребує участі кожного виборця до завершення голосування та що відбудеться, якщо один з учасників припинить виконання протоколу?

Кожен бюлетень зашифровано ключами всіх виборців, а закритий ключ має лише власник, тому зняти шар учасника може тільки він сам; передача набору відбувається по ланцюжку. Якщо учасник не передасть набір чи не зніме свій шар, бюлетені залишаться зашифрованими, і голосування не може завершитися: у демонстрації після відмови C виборець D отримує NOT_RECEIVED. Таємниця при цьому зберігається, але голосування доводиться повторювати, і будь-хто може зірвати його.

7. Як після завершення голосування кожен учасник може самостійно перевірити правильність кінцевого результату?

Останній виборець публікує набір відкритих бюлетенів зі своїм ЕЦП. Кожен учасник перевіряє ЕЦП відкритим ключем зі своєї копії списку, перевіряє, що бюлетенів стільки ж, скільки учасників, самостійно рахує голоси і порівнює з оголошеним результатом. Оскільки під час розшифрування кожен знайшов свій RP в обох раундах, він знає, що його бюлетень дійшов до кінця. Розбіжність підрахунку, як у сценарії з хибним підсумком, видно кожному.

8. Які основні недоліки та обмеження має протокол електронного голосування без виборчої комісії?

Складність: кількість операцій і обсяг даних швидко ростуть із кількістю виборців (у посимвольній реалізації довжина бюлетеня зростає як 4^N), тому протокол придатний лише для малих груп. Залежність від кожного: відмова одного учасника зупиняє голосування. Змова: учасники можуть обмінятися знаннями й зменшити анонімність інших, а якщо всі, крім одного, розкриють свої голоси, вибір останнього видно з результату. Останні в черзі дізнаються результат раніше за інших, а після видалення RP детерміноване RSA дозволяє їм розпізнавати голоси (D дізнався вибір E). Виборець, знайшовши свій RP, бачить лише наявність бюлетеня, а не його відкритий вміст, тому підміну бюлетеня виборця, етап якого вже минув, виявити складно. Нарешті, у разі зупинки протоколу на першому раунді через перемішування неможливо встановити, хто саме підмінив бюлетень.
