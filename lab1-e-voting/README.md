# Лабораторна робота №1 (ПАЕГ) — простий протокол Е-голосування

Програмна реалізація простого протоколу електронного голосування: **2 кандидати, 5 виборців**,
RSA використовується і для шифрування бюлетенів, і для ЕЦП. Реалізація навчальна: уся арифметика
RSA, хеш квадратичної згортки та розширений алгоритм Евкліда написані вручну, без криптобібліотек.

## Запуск

```bash
npm start        # демонстрація протоколу: позитивні та негативні сценарії
npm test         # 21 модульний тест (node:test)
npm run typecheck
```

Допоміжні команди (потрібні лише для перегенерації матеріалів звіту):

```bash
npm run shots    # скріншоти виконання → assets/*.png
npm run report   # звіт → report/Звіт_ЛР1_ПАЕГ.docx і .pdf
npm run video    # відеопояснення → video/lab1-demo.mp4 (≈8 хв)
```

Потрібен Node.js ≥ 22.6 (TypeScript виконується напряму, без збірки).
Зовнішніх залежностей у рантаймі немає — лише `typescript` і `@types/node` для перевірки типів.

## Структура

| Файл | Призначення |
| --- | --- |
| `src/bigint-math.ts` | `modPow`, розширений алгоритм Евкліда, `modInverse`, тест Міллера — Рабіна, генерація простих |
| `src/rsa.ts` | генерація пари ключів, блокове шифрування/розшифрування, хеш `Hᵢ = (Hᵢ₋₁ + Mᵢ)² mod n`, ЕЦП |
| `src/types.ts` | бюлетень, конверт, список виборців, причини відхилення, канонічна серіалізація |
| `src/voter.ts` | виборець: власні ключі, заповнення + підписання + шифрування бюлетеня |
| `src/commission.ts` | ВК: списки виборців і кандидатів, розшифрування, усі перевірки, підрахунок голосів |
| `src/main.ts` | сценарій демонстрації (позитивні + негативні випадки, нічия, зведення властивостей) |
| `tools/capture.ts`, `tools/shots.sh` | скріншоти терміналу для звіту (ANSI → HTML → PNG через headless Chrome) |
| `tools/video.ts`, `tools/video.sh` | збірка відео з поясненням і демонстрацією роботи |

## Кроки протоколу в коді

1. **Підготовка** — `new Voter(...)` генерує пару ключів кожного виборця; `commission.registerVoter(ПІБ, відкритий ключ)`
   формує список допущених виборців; ВК має власну пару ключів, її відкритий ключ публікується.
2. **Формування бюлетеня** — `voter.fillAndSign(candidateId)`: канонічний JSON бюлетеня → хеш квадратичної
   згортки → `ЕЦП = H^d mod n`; `voter.seal(...)` шифрує пару «бюлетень + ЕЦП» відкритим ключем ВК.
3. **Обробка у ВК** — `commission.receive(envelope)`: розшифрування `m = c^d mod n`, перевірка наявності
   у списку, перевірка ЕЦП (`H` проти `H_c = ЕЦП^e mod n`), звірка ПІБ, перевірка повторного голосування,
   перевірка коректності заповнення, після прийняття — відмітка `hasVoted`.
4. **Підрахунок** — `commission.publishResults()`: підсумки по кандидатах, явка, кількість відхилених спроб,
   визначення переможця або фіксація нічиєї.

## Перевірені сценарії

Позитивні: коректний бюлетень приймається; 5 бюлетенів рахуються (3:2); рівний розподіл дає нічию.

Негативні: `NOT_IN_LIST` (виборця немає у списку), `ALREADY_VOTED` (повторне голосування),
`BAD_SIGNATURE` (голосування від чужого імені та підміна бюлетеня по дорозі),
`INVALID_BALLOT` (правильний ЕЦП, але неіснуючий кандидат), `UNDECRYPTABLE` (бюлетень зашифровано чужим ключем).
