# Лабораторна робота №2 (ПАЕГ) — протокол Е-голосування зі сліпими підписами

Програмна реалізація протоколу електронного голосування зі сліпими підписами: **2 кандидати, 5 виборців**,
RSA використовується і для сліпого ЕЦП, і для шифрування бюлетенів. Реалізація навчальна: уся арифметика
RSA, хеш квадратичної згортки, сліпий підпис і розширений алгоритм Евкліда написані вручну, без криптобібліотек.

## Запуск

```bash
npm start        # демонстрація протоколу: позитивні та негативні сценарії
npm test         # 29 модульних тестів (node:test)
npm run typecheck
```

Допоміжні команди (потрібні лише для перегенерації матеріалів звіту):

```bash
npm run shots    # скріншоти виконання → assets/*.png
npm run report   # звіт → report/Звіт_ЛР2_ПАЕГ.docx і .pdf
```

Потрібен Node.js ≥ 22.6 (TypeScript виконується напряму, без збірки).

## Структура

| Файл | Призначення |
| --- | --- |
| `src/bigint-math.ts` | `modPow`, розширений алгоритм Евкліда, `modInverse`, тест Міллера — Рабіна, генерація простих |
| `src/rsa.ts` | генерація пари ключів, блокове шифрування/розшифрування, хеш `Hᵢ = (Hᵢ₋₁ + Mᵢ)² mod n`, перевірка ЕЦП |
| `src/blind-signature.ts` | `H' = H·rᵉ mod n`, `S' = (H')ᵈ mod n`, `S = S'·r⁻¹ mod n` |
| `src/types.ts` | бюлетень, набори, запит, розкриття, конверт, причини відмов, строга серіалізація бюлетеня |
| `src/voter.ts` | виборець: 10 наборів, маскування, розкриття 9 наборів, зняття маскування, голосування, перевірка свого ID |
| `src/commission.ts` | ВК: списки, перевірка особи, вибір 9 з 10, перевірка наборів, сліпий підпис, приймання бюлетенів, підрахунок |
| `src/main.ts` | сценарій демонстрації (позитивні + негативні випадки, статистика виявлення шахрайства) |
| `tools/` | скріншоти терміналу та генерація звіту |

## Кроки протоколу в коді

1. **Підготовка** — `new ElectionCommission(...)` генерує ключі ВК; `registerVoter(ПІБ, документ)` формує список.
2. **Набори (кроки 2–4)** — `voter.prepare(...)`: 10 наборів з різними випадковими ID, по бюлетеню на кандидата, хеші маскуються.
3. **Підписування (кроки 5–10)** — `commission.requestSigning(...)` перевіряє особу/список/повторність і обирає 9 наборів;
   `voter.reveal(...)` розкриває їх; `commission.completeSigning(...)` перевіряє набори і наосліп підписує десятий;
   `voter.acceptSignatures(...)` знімає маскування й перевіряє підписи.
4. **Голосування (кроки 11–13)** — `voter.vote(...)` шифрує бюлетень із підписом ВК без ПІБ;
   `commission.receive(...)` розшифровує, перевіряє ЕЦП ВК, кандидата і унікальність ID.
5. **Результати (крок 14)** — `commission.publishResults()` публікує підсумки та список ID з підписаними бюлетенями;
   `voter.checkPublished(...)` перевіряє свій голос.

## Перевірені сценарії

Позитивні: 5 виборців отримують підписані набори й голосують (3:2); кожен знаходить свій ID; ВК не знає жодного ID поданих бюлетенів.

Негативні: `NOT_IN_LIST`, `IDENTITY_MISMATCH`, `ALREADY_ISSUED` (повторний набір), `BAD_SET` (некоректний набір серед
розкритих; підміна бюлетеня під час розкриття), `REFUSED_EARLIER`, `DUPLICATE_ID` (два бюлетені з одного набору, повторне
надсилання), `BAD_SIGNATURE` (зміна вибору, бюлетень без підпису ВК), `UNDECRYPTABLE`, підміна опублікованого запису.
Статистичний експеримент: один некоректний набір виявляється ≈90% випадків.
